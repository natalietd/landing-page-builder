# Сборка

Собирай по утверждённому плану (`framework.md` §5) и визуальной системе (`visual-system.md`).
Планка: владелец может выпустить страницу после мелких правок — без структурной переделки.

## 1. Технический таргет

- **Есть проект** (`package.json`, фреймворк, Tailwind/CSS-модули, компоненты): собирай в его стеке
  и конвенциях; переиспользуй компоненты, токены, роутинг.
- **Есть живой лендинг в репозитории:** это режим B — иди по `redesign.md`; перерисовывай на месте,
  сохрани порядок секций, ID, структуру.
- **С нуля:** один самодостаточный `index.html`, Tailwind через CDN, ванильный JS — дизайн заново
  под эту нишу по визуальной системе (без чужой страницы или шаблона). Есть тема tweakcn →
  минимальный Vite/Next + Tailwind + shadcn/ui, чтобы переменные темы применились.
- Неясно → выбери вариант по умолчанию выше и скажи об этом.

## 2. Тексты

- Весь видимый текст — на языке и в регистре из брифа. Идентификаторы и комментарии в коде — на английском.
- Конкретно, без воды; убирай оговорки и пустые прилагательные.
- Только наши факты. Паттерны конкурентов — да, их предложения — никогда.
- **Описывай, как продукт работает на самом деле.** Сценарий, лимиты и частота («одна в день»,
  «без ограничений», «свои темы») — от владельца или из самого продукта (код, настройки, экраны).
  Никогда не выводи их из одной подписи на скриншоте вроде «Today». Не уверен — спроси или не пиши.
- Сохраняй исходные тексты из карточки/живого лендинга, если не просили переписать; заголовки
  можно ужать, поясняющие строки не вырезай.
- Каждый CTA = действие + выгода («Начать бесплатно — первые клипы через 5 минут»), никогда не
  «Отправить»/«Подробнее».
- Выгоды повторяются прямо перед оффером.

## 3. Медиа

- **Медиа продукта идут на страницу**: скриншоты, записи экрана, демо, реальные результаты/работы,
  фото товара — от владельца, из карточки или с сайта самого продукта.
- Формат — как в нише (см. визуальную систему). Видео: autoplay muted loop + `playsinline` + poster.
- Нет ассета → оставь место: пустая рамка реального размера/пропорции ассета с тихой подписью, что
  туда встанет (+ HTML-комментарий `TODO`). Никогда фейковый скриншот, никогда сток вместо продукта,
  никогда ассеты конкурентов — и никогда не убирай слот только потому, что ничего не готово.
- **«Как работает» = интерфейс на каждом шаге.** У каждого шага свой слот под экран — заполненный или пустой.
- **Мобильные приложения: «как работает» — шахматкой.** Только этот блок: ряд на каждый шаг,
  скриншот телефона **целиком** (не обрезать посреди экрана) в рамке на мягкой цветной подложке, текст
  рядом, ряды чередуются лево/право (на телефоне — столбиком). **Остальные блоки — своя раскладка**
  (карточки, сетка, список, сплит…). Не повторяй шахматку или любую одну раскладку по всей странице;
  каждый блок должен отличаться от соседей.
- **Никаких тяжёлых тёмных блоков, перетягивающих внимание.** Контрастная полоса не должна быть
  заметнее первого экрана: никаких чёрных плит с обрезанными экранами. Для приложений — светлые
  пастельные поля в каждом ряду.
- **Несколько результатов = один ряд-галерея**: каждый элемент — отдельный результат со своей
  подписью (категория · источник · фрагмент). Никогда не группируй парами по источнику: два рядом
  читаются как «до/после». Чередуй источники, чтобы одинаковые не стояли рядом; у каждого элемента
  своя обложка или первый кадр.
- Если показываешь продукт с примерными цифрами — подпиши «демо-данные».
- **Никогда не обрезай суть экрана.** Если скриншот показан, его главный элемент (правка, кнопка,
  цифра, уровень) виден целиком. Лучше весь экран. Обрезать можно только пустое место — и посмотри на
  результат, прежде чем оставить.
- Осмысленный `alt`, разумный вес файлов, lazy-load ниже первого экрана.

## 4. Подключение CTA

```js
// TODO: replace with the real destination
const PRODUCT_URL = "TODO_REPLACE_ME"; // или BOOKING_URL для записи на звонок
```

- В продукт → все главные кнопки ведут на `PRODUCT_URL`. Поле продукта (вставить ссылку / загрузить)
  может передать значение в URL или в собственный сценарий продукта.
- Звонок → встрой календарь в блок Оффера (iframe в духе Calendly); кнопки скроллят к нему или
  открывают `BOOKING_URL`. Поля записи — у календаря.
- Никаких своих лид-форм и квизов.

## 5. Оффер и цены

Заголовок-выгода → что будет после клика → тарифы с CTA на каждом → тариф с лучшей ценностью выделен
(бейдж + рамка) → единицы переведены для аватара → снятие риска → возражения/FAQ → финальный CTA.
Только реальные цены. Формат — как базовый в нише по разбору.

## 6. QA — в браузере, до передачи

Открой страницу (десктоп ~1440px, потом 375px). Пройди каждую секцию, а не только первый экран.
Быстрее всего сравнивать так: прогони скрипт съёмки и по своей странице
(`node <skill>/scripts/capture.mjs --out research/qa "file://$PWD/index.html"`) и смотри наши
`sections/NN.png` рядом с конкурентами. В браузере также проверь: нет горизонтального скролла на
375px, нет ошибок в консоли.

**Против плана**
- [ ] Каждая строка таблицы плана есть на странице; веса выглядят верно (Преимущества + Продукт ≈ 60%).
- [ ] Весь базовый уровень рынка на месте.
- [ ] Взятые практики реализованы в запланированном блоке.
- [ ] Главный пробел виден на первом экране или в первом преимуществе.

**Против эталона** (`reference-standard.md`)
- [ ] Все 10 пунктов планки §1 выполнены (продукт на первом экране, надзаголовок с аватаром,
      выделение в заголовке, микротекст CTA, реальный экран на шаг, результат показан,
      надзаголовки, цифры, повтор выгод перед ценой, финальный CTA повторяет механику).
- [ ] Каждый блок использует названный паттерн из §2 и сделан на уровне §3–4 — положи наши
      секции рядом со снимками эталона; наши не должны выглядеть на уровень ниже.

**Против конкурентов** (скриншоты рядом)
- [ ] Наш первый экран не менее ясен, чем у лидера: что, для кого, зачем, CTA — за 5 секунд.
- [ ] Продукт показан не менее конкретно, чем у лучшего конкурента.
- [ ] Выглядит как часть этой ниши (визуальная система применена), но не клон.
- [ ] Нет текстов, цифр и ассетов конкурентов.

**Базовые правила**
- [ ] Сильный первый экран; аватар назван; **визуал продукта в первом экране 1440×900** (обрежь `full.png` до 900px и посмотри).
- [ ] Посторонний человек по одному первому экрану понимает, **что происходит в продукте**: ключевой момент на экране, а если он не очевиден — его объясняют пронумерованные выноски.
- [ ] Каждый CTA связан с выгодой; оффер говорит, что будет после клика.
- [ ] Одно главное действие выбранного типа; константа `PRODUCT_URL`/`BOOKING_URL`; нет лид-форм и квизов.
- [ ] «Как работает» показывает реальный интерфейс на каждом шаге — или пустую подписанную рамку на шаг.
- [ ] Реальные медиа продукта или подписанные TODO; нет выдуманных доказательств/цен.
- [ ] Тексты на нужном языке/в нужном регистре; не вырезаны.
- [ ] Прочитай каждый заголовок вслух: одна мысль, одна естественная фраза. Никаких хвостов,
      пришитых из текста ради выгоды (например, «Три шага — и клипы готовы, пока видео ещё обрабатывается»).
- [ ] Проход по заголовкам сделан: каждый H1/H2 продаёт результат или конкретную сцену; ярлыки — в надзаголовках.
- [ ] Каждое утверждение о том, как работает продукт (частота, лимиты, свои темы, платформы),
      сверено с владельцем или самим продуктом, а не угадано по скриншоту.
- [ ] Блок болей есть, только если по разбору он у большинства конкурентов / у лидера.

**Экраны и раскладка**
- [ ] На каждом скриншоте главный элемент виден целиком; рамку устройства не обрезает контейнер;
      плавающие карточки не закрывают содержимое экрана.
- [ ] Мобильное приложение: «как работает» — шахматка из целых телефонов; **ни один другой блок** её не повторяет.
- [ ] Соседние блоки выглядят по-разному; одна раскладка не повторяется по странице.
- [ ] Контрастная секция поддерживает первый экран, а не перекрикивает его.

**Качество**
- [ ] Токены используются; один акцент в рамках бюджета; глубина, а не плоская пустота; hover + focus.
- [ ] Мобильный: нет горизонтального скролла, текст читается, медиа и CTA помещаются; видео играют.
- [ ] Нет ошибок в консоли; картинки грузятся; семантичные заголовки; контраст в норме.
- [ ] Каждый заголовок читается на своей полосе: общий цвет `h1–h3` не должен перебивать светлую
      полосу или белую карточку (базовые цвета — через `:where()`).
- [ ] Многострочные акцидентные заголовки не слипаются: межстрочный задан на самом заголовке
      (~1.1–1.2); размеры Tailwind `text-*` его сбрасывают.

Исправь провалы до показа владельцу.

## 7. Передача

- Как посмотреть: если на странице локальные файлы (`assets/…`), **раздай её по http** (например,
  `python3 -m http.server --directory <папка>`) и покажи этот адрес. Панель превью, которая открывает
  файл как статичный снимок, теряет относительные картинки — владелец видит подписи вместо экранов.
  Перед передачей открой ровно тот адрес, что даёшь владельцу, и проверь, что все картинки загрузились
  (прокрути ниже ленивых).
- Коротко: какие практики взяты, с какого пробела ведём, чью визуальную систему повторяем.
- Каждый `TODO` (ссылки, ассеты, доказательства, цены) и нерешённые конфликты с нашими правилами.
- Если боли сокращены/убраны — скажи и почему (нет у конкурентов / нет реальных фактов / решил владелец).
- Что стоит протестировать дальше (например, альтернативную формулу заголовка из разбора).
