# Режим B — улучшить дизайн существующего лендинга

Страница уже есть (ссылка, файл в репозитории или скриншот). Владелец хочет, чтобы она **выглядела
и работала лучше**, а не новую историю продукта. Сохраняем его факты и слова; **дизайн делаем заново**.

**«Редизайн» значит новый внешний вид.** Текущие палитра, шрифты и стиль — это то, что мы заменяем,
а не бренд, который надо беречь. Если блоки просто переложены в старых цветах и шрифтах — это провал.

## 1. Что остаётся, что меняется

| Остаётся (если владелец не сказал иначе) | Меняется |
|------------------------------------------|----------|
| Факты продукта, цены, оффер, адреса CTA | Визуальная система: токены, пара шрифтов, акцент, ритм, карточки |
| Порядок секций и якоря/ID | Иерархия внутри блока: надзаголовок, заголовок, лид, медиа, CTA |
| Тексты владельца (заголовки можно ужать, пояснения не режем) | *Паттерн* блока (например, текстовый список → шаги с реальными экранами) |
| Логотип и название продукта | **Весь внешний вид**: палитра, шрифты, формы, фоны, ритм — заново (§3 Визуал) |
| Фирменные цвета **только** если есть брендбук или владелец назвал их брендом | Подача медиа: реальный UI в рамках браузера/устройства, пустые подписанные рамки, где нет |
| Стек и компоненты репозитория | Микротекст CTA, отступы, мобильная вёрстка, состояния |

Структурный пробел (нет болей, *хотя они есть у конкурентов*, нет «как работает», CTA без выгоды, нет повтора выгод перед ценой)
**предлагается, а не добавляется молча**. Вынеси его на чекпоинт с нарушенным правилом.

## 2. Процесс

| # | Фаза | Результат |
|---|------|-----------|
| 0 | **Работай в копии**, если страница живая/задеплоена: `before.html` не трогаем, собираем `index.html` рядом; живой файл заменяем только после «ок» владельца | `before.html` + рабочая копия |
| 1 | **Снять текущую страницу**: `capture.mjs` по живой ссылке или `file://…/before.html` | `research/before/` секции + `page.json` |
| 2 | **Аудит**: оцени каждую секцию по нашей структуре (5 задач + базовые правила) и эталону (`reference-standard.md` §1 планка, §2 паттерны, §3–4 ремесло) | Таблица аудита |
| 3 | **Проверка конкурентов** (2–3 страницы, обязательно): внешний вид ниши, как показывают продукт, есть ли блок болей. Это основа **новой** визуальной системы | 3–5 строк в аудите + новая визуальная система |
| 4 | **План редизайна**: по каждой секции — оставить / перерисовать / сменить паттерн + выбранный паттерн + визуальная система → **чекпоинт с владельцем** | Таблица плана |
| 5 | **Сборка**: правка на месте (тот же стек, порядок, ID) на уровне качества `examples.md` §D, в **новой** визуальной системе (старый вид не переиспользуем) | Страница |
| 6 | **QA**: снять заново в `research/after/`, сравнить до/после по секциям, пройти `build.md` §QA | До/после + передача |

### Таблица аудита

| # | Секция (как на странице) | Наша задача | Проблемы (иерархия · медиа · текст · CTA · мобильный) | Нарушенный пункт планки / правило | Решение: оставить / перерисовать / сменить паттерн → паттерн |
|---|---|---|---|---|---|

Частые находки:
- на первом экране иллюстрация вместо продукта;
- аватар не назван;
- под CTA нет микротекста;
- «как работает» без экранов;
- стена одинаковых карточек без иерархии;
- цена без повтора выгод и без цены за единицу;
- много акцентов;
- плоские пустые секции;
- сломанная мобильная вёрстка;
- невидимый текст (заголовок окрашен под другой фон);
- **факты, которые расходятся между секциями**: один и тот же клип или цифра подписаны в двух местах по-разному. Сверяй каждый повторяющийся факт.

## 3. Правила

- **Сначала смысл, украшения — никогда.** Каждое изменение должно делать задачу блока понятнее. Не
  добавляй секции, вкладки и эффекты «для красоты».
- **Правило реального интерфейса действует**: если секция переходит в шаги или зигзаг функций, а
  скриншотов нет — ставь пустые рамки нужного размера с подписью и `TODO`.
- **Визуал: собери новую систему** по `visual-system.md` из ниши + конкурентов + ремесла эталона.
  Логотип и название сохраняем. Фирменный цвет — только если есть брендбук или так сказал владелец:
  тогда он может остаться акцентом, всё остальное всё равно новое.
- До сборки запиши **3 видимых отличия** от старого вида (например, «бежевая бумага → чистый белый
  + тёмно-зелёная полоса», «системный шрифт → характерная пара», «плоские карточки → устройства в
  рамках на цветных подложках»). Не можешь назвать три — это ещё не редизайн.
- Правки текста ограничены: ужать заголовки, добавить надзаголовки, микротекст CTA, жирные начала
  строк. Всё крупнее → предложи на чекпоинте.
- **Новый заголовок-выгода собирается только из фактов, которые уже есть на странице.** «Сделать
  выгодой» не значит придумать обещание («публикуйте без правок», «час → 5 клипов» над 15-минутным
  примером). Чипсы и счётчики — так же: «исходник 14:45», а не «14:45 → 2 клипа», если показаны только два.
- **FAQ и финальный CTA** — безопасные добавления, если каждый ответ собран из фактов, которые уже
  есть на странице. Предложи и собери после «ок» владельца. Блок болей — по `framework.md` §2:
  только если он есть у конкурентов и только с реальными цифрами.
- В передаче покажи пары **до/после** (та же секция, та же ширина) и список предложенных, но не
  сделанных структурных изменений.
